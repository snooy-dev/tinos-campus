# RTTR 직렬화 적합성 검증

## 결과

현재 엔진의 MSVC v145 / C++23 환경에서 **RTTR를 속성 메타데이터 기반으로 채택할 수 있는 근거를 확인했다.**
Debug와 Release에서 아래 검증이 통과했다. 제품 엔진에 통합한 결과는 아니며, RTTR가 완성된 레벨 로더를 제공한다는 뜻도 아니다.

| 검증 | 결과 |

| 기반 클래스 참조에서 파생 타입 및 상속 속성 조회·수정 | 통과 |
| 에디터용 메타데이터 조회, 중첩 속성 수정·반영 | 통과 |

| 기존 엔진의 Transform 모듈 및 GLM vec3/quaternion 왕복 변환 | 통과 |

검증 날짜: 2026-11-09. 컴파일러: MSVC 14.51.36231 (Visual Studio Community 2026).

## 의존성과 재현

루트 manifest 및 제품 프로젝트는 수정하지 않는다. 이 디렉터리의 독립 manifest는 기존 baseline
`d4c0a46cb8f63e5c9fa007d13baf1cb3e43bf7e3`을 사용한다.

| 직접 의존성 | 설치된 버전 | 라이선스 |
|---|---|---|
| rttr | 0.9.6+20210811#1 | MIT |
| nlohmann-json | 3.12.0#2 | MIT |
| glm | 1.0.3 | MIT 선택 가능 |

RTTR 포트가 rapidjson 2025-02-26#1도 의존성으로 설치한다. 검증 코드는 nlohmann/json을 사용한다.
설치된 라이선스 전문은 `build/serialization-probe/vcpkg_installed/x64-windows/share/<package>/copyright`에 있다.

저장소 루트에서 PowerShell로 실행한다.

```powershell
./tests/serialization_probe/run.ps1
```

다른 Visual Studio 경로는 `-VisualStudioRoot`로 지정한다. 스크립트는 검증 전용 의존성 설치,
Debug·Release 재빌드와 실행을 수행한다. 모든 산출물은 무시되는 `build/serialization-probe`에 저장된다.
`dependencies.log`, `debug-build.log`, `release-build.log`, `debug-run.log`, `release-run.log`로 결과를 확인한다.
실제 사용자 빌드 환경을 사용해야 한다. 이번 검증에서는 다른 격리 환경에서 빌드했을 때 C1902 PDB 오류가
발생했고, 동일한 사용자 환경에서 재빌드하여 해소했다.

## 확인된 제약

- **헤더 순서:** RTTR 헤더를 `import SerializationProbe;`보다 먼저 포함해야 한다.
  반대로 배치하면 이 MSVC 환경에서 `rttr::array_range` 등의 재정의 오류가 발생했다.
  모델의 global module fragment에서 RTTR를 포함하고, 등록 파일에서는 같은 모듈의 구현 단위를 사용한다.
- **경고:** RTTR 내부에서 C4996 (`std::aligned_storage`의 C++23 사용 중단 예정 경고),
  등록 코드의 `std::reference_wrapper<int/Stats>` 인스턴스화에서 C4506 경고가 나온다.
  억제하거나 라이브러리를 패치하지 않았다. 현재 테스트는 링크·실행에 성공했지만
  모든 사용자 타입과 향후 컴파일러까지 안전하다고 결론 내릴 수 없다.
- **링크 범위:** 등록 코드는 실행 파일에 직접 포함했다. static library에 넣었을 때의
  등록 코드 제거, DLL 간 타입 공유, 플러그인 로딩은 검증하지 않았다.
- **오류 처리:** JSON 접근에서 발생한 표준 예외는 Capture/Restore 경계에서 실패 결과로 변환한다.
  엔진의 치명적 오류 처리와 일반 로그 정책을 변경하지 않는다. 예외 비활성화 빌드는 검증하지 않았다.

## RTTR가 대체하는 부분과 엔진에 남는 부분

RTTR는 타입/상속/생성자/속성 등록, 런타임 속성 순회, 값 조회·설정, 컨테이너 접근 및
에디터 메타데이터 조회를 담당한다. `registration.cpp`의 속성 정의를 편집과 직렬화에서 함께 사용한다.
nlohmann/json은 검증용 메모리 데이터와 문자열 변환만 담당한다. 파일 형식 채택은 확정하지 않는다.

`codec.cpp`에 직접 작성한 부분은 값 검증, 객체 ID, 소유권, 생성 순서, 참조 연결, 실패 시 정리다.
이 부분은 라이브러리 도입 후에도 엔진에 필요하다. 이번 코드는 Pawn/Component만 생성하는
제한된 검증기이며 그대로 제품 로더로 편입하지 않는다. ID는 저장 시 순회 순서로 부여하고,
복원은 ID 순서로 생성한다. 영속 에디터 ID, 임의 순서 정책, 마이그레이션, 입력 크기 제한은 구현하지 않았다.
재귀 깊이·대형 배열에 대한 자원 제한과 성능도 검증하지 않았다.

## 실제 엔진에 적용할 때 필요한 변경

1. GameObject와 파생 Actor/Component/GameMode 계층에 `RTTR_ENABLE`을 적용할지 결정해야 한다.
   이번 검증 모델은 이 매크로를 사용했다. 기존 제품 객체에는 추가하지 않았다.
2. 각 저장 대상 타입의 속성을 별도 등록 구현 파일에 선언한다. private 상태는 접근자를 사용하고,
   Transform처럼 setter에 불변식 처리가 있는 속성은 복원도 setter를 통과시킨다.
3. Scene/Actor의 기존 소유권 API를 통해 새 객체를 편입하는 생성 경로와 에디터 ID를 구현해야 한다.
   생성에 필요한 컨텍스트는 코드에서 전달하며 메모리 주소를 직렬화하지 않는다.
4. 메시 핸들은 에셋 경로와 분리해 복원해야 한다. 이번 검증은 경로 문자열만 다루며 GPU 로딩은 하지 않는다.

추천은 **RTTR를 메타데이터 후보로 유지하고 위 제약을 반영해 통합 설계를 진행하는 것**이다.
타입별 에디터 메타데이터와 직렬화 정보를 두 번 작성할 필요가 줄어드는 점은 확인했다.
라이브러리 간 성능 우열이나 코드 감소율은 측정하지 않았다.

후속 실제 엔진 통합에서는 이 소형 검증보다 복잡한 모듈 경계에서 MSVC C1116이 추가로 발생했다.
제품 타입은 RTTR 타입 조회 구현을 `.cpp`로 분리했고, SDL 검사 때문에 C4996을 RTTR 헤더
구간에서만 억제했다. 최신 통합 방식과 실제 엔진 회귀 테스트는 루트 README를 따른다.
